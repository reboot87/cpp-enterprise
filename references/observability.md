# 可观测性

目标:线上问题能在 5 分钟内定位到模块和变更,不靠重启和猜测。

## 1. 三类信号

| 信号 | 用途 | 要求 |
|---|---|---|
| 日志 | 事件与上下文 | 结构化、可检索、带关联 ID |
| 指标 | 趋势与告警 | 低基数、命名稳定 |
| 追踪 | 跨线程/跨服务调用链 | 传播 trace_id |

三者用同一套 ID 关联:request_id、trace_id、span_id。

## 2. 日志

- 结构化(JSON),字段固定:`ts`、`level`、`service`、`event`、`trace_id`、`request_id`、`error_code`、`duration_ms`。
- 级别语义:ERROR(需人处理)、WARN(可自愈)、INFO(状态变化)、DEBUG(默认关)。
- 禁止裸 `printf`/`cout` 上线;统一 logger。
- 热路径 INFO 异步且队列有界;队列满按策略丢弃并计数,不阻塞业务。
- 不打印密钥、token、口令、完整证件号;敏感字段脱敏或哈希。
- 每条错误日志带:操作、关键参数、错误码、重试次数、耗时。
- 禁止在循环里无节制打日志(采样或聚合)。
- 日志量有预算(每请求字节数、每秒条数);超预算降级为采样,成本异常上涨视为回归。

## 3. 指标

- 命名:`<domain>_<subject>_<unit>`,如 `http_requests_total`、`request_duration_seconds`。
- 类型:Counter(只增)、Gauge(可增可减)、Histogram(延迟/大小)。
- 基数上限:禁止把用户 ID、URL 全路径、错误原文放标签;标签集 ≤ 10 个,单指标时间线 ≤ 1 万。
- 延迟用 Histogram,分桶覆盖 p50–p999;不要只报平均值。
- 每个对外接口至少:请求数、错误数、延迟、在途数。
- 资源:CPU、内存、fd、线程、队列深度、连接池使用率。

## 4. 追踪

- 传播 W3C `traceparent`;跨线程/异步任务传递上下文。
- 采样策略明确(头部采样或尾部采样),采样率可配。
- span 命名稳定(`http.server`、`db.query`),不拼参数。
- 关键路径必须有 span:入口、依赖调用、队列等待、序列化。

## 5. SLO 与错误预算

- 每个对外服务定义 SLI(可用性、延迟)与 SLO(如 99.9%/30 天)。
- 错误预算耗尽时冻结非必要发布,优先稳定性。
- 告警基于症状(错误率、延迟、饱和度),不基于单条日志。
- 告警必须可执行:附 runbook 链接、影响面、缓解步骤。

## 6. 健康检查

- liveness:进程活着,不检查外部依赖。
- readiness:能接流量,检查关键依赖与初始化完成。
- 启动/关闭过程有明确状态,避免流量打到未就绪实例。

## 7. Runbook 最小内容

服务用途、部署拓扑、依赖与端口、启停步骤、常见故障与处理、回滚步骤、升级步骤、联系人。

## 8. 崩溃与生产诊断

- 崩溃产生 minidump/core dump,带 build id,能对应到符号。
- 符号文件单独归档,提供 symbol server 或等价索引;不发布带完整符号的二进制。
- 崩溃上报聚合去重,按版本/栈顶分组;上报限速,避免风暴。
- dump 可能含敏感数据:加密传输、访问控制、限定保留期。
- 生产剖析用低开销采样(continuous profiling),采样率可调。
- 临时调试埋点默认关闭,开启需有开关和到期时间。

## 9. 反模式

- 日志只写"error occurred"没有上下文。
- 指标标签带用户 ID / 请求 ID 导致基数爆炸。
- 只在出事后加监控,没有基线。
- 告警风暴,没有聚合和抑制。
- 追踪采样 100% 拖垮性能,或 0% 等于没有。
- 健康检查调外部依赖,依赖抖动导致实例被批量摘除。
