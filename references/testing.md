# 测试体系

## 1. 层级与职责

| 层级 | 测什么 | 占比参考 | 约束 |
|---|---|---|---|
| 单测 | 单个类/函数,含边界与错误路径 | ~70% | 毫秒级;无 IO/网络/真实时钟 |
| 集成 | 模块 + 真实依赖(DB、socket、文件) | ~20% | 可起临时实例;失败可复现 |
| 契约 | 模块间/服务间接口约定 | 每个接口 ≥1 套 | 双方共用同一套契约测试 |
| E2E | 关键用户路径 | ~10% | 少量、稳定、带超时 |
| 手工/探索 | 交互、异常场景 | 按需 | 有记录,不替代自动化 |

原则:能用单测证明的不上升到集成;关键路径必须有 E2E。

## 2. 可测性设计

- 依赖注入;不在构造函数里 new 全局资源。
- 时间、随机数、ID、网络、文件系统可替换(clock/RNG/transport 接口)。
- 禁止隐式全局状态;测试可并行执行。
- 公开行为而非实现细节;重构不应大面积改测试。

## 3. 覆盖率与判据

- 口径:行 + 分支;安全/并发关键代码看 MC/DC。
- 阈值:核心 ≥80%,整体 ≥60%,新增/变更行 ≥90%。
- 覆盖率是下限不是目标;禁止为凑数写无断言测试。
- 关键算法与解析器加 mutation testing,目标分数 ≥60%。
- 覆盖率看趋势:下降即失败,不只看绝对值。

## 4. 测试类型

| 类型 | 用途 | 工具参考 |
|---|---|---|
| 属性测试 | 不变量(编码/解码往返、排序幂等) | RapidCheck、Hypothesis 思路 |
| fuzz | 解析器、协议入口 | libFuzzer、AFL++ |
| golden | 输出格式、序列化稳定性 | 版本化基准文件 |
| 兼容性 | 多 OS/编译器/依赖版本 | CI 矩阵 |
| 长稳/压测 | 泄漏、吞吐、尾延迟 | 见 `performance.md`、`robustness.md` |
| 故障注入 | 依赖异常、资源耗尽 | 见 `robustness.md` |

## 5. 确定性与 flaky

- 禁止 `sleep` 等时序;用 fake clock / 条件变量 / 轮询超时。
- 随机数固定种子;测试间不共享状态;临时目录隔离。
- flaky 测试立即隔离(quarantine),修复 SLA ≤5 天;禁止用重跑掩盖。
- 失败要能本地一条命令复现,CI 保存失败产物与日志。

## 6. 测试数据

- 不直接用生产数据;必须用则脱敏并登记。
- fixture 版本化、最小化;大文件用生成器而非入库。
- 每个 bug 的输入精简后作为回归用例保留。

## 7. CI 执行

- 单测在每次提交;集成/E2E 在合并前;长稳/fuzz/mutation 在 nightly。
- 每个测试有超时;整体有硬上限,超时视为失败。
- 分片并行,分片间无共享状态。
- 启用 ASan/UBSan/TSan 矩阵;失败保留 core/日志。

## 8. 缺陷流程

1. 先写失败测试,复现。
2. 最小化输入。
3. 修根因,不绕过断言。
4. 回归测试随修复一起合并。
5. 同类问题全仓排查。

## 9. 持续 fuzz

- 解析器、协议、序列化入口必须有 fuzz target。
- 种子语料入库;崩溃输入自动进入回归语料。
- 本地/CI 跑短时 fuzz;nightly 跑长时或接入 OSS-Fuzz 类服务。
- 崩溃去重、分派、修复有流程;修复后语料保留。
- 跟踪 feature coverage;长期不增长说明 harness 失效。

## 10. 反模式

- 只测 happy path。
- 测试里加 `if` 分支或跳过逻辑。
- 用重跑、`sleep`、放宽断言解决 flaky。
- 断言实现细节,重构即全红。
- 覆盖率靠排除文件/加 `// LCOV_EXCL` 达标。
- 测试依赖执行顺序或共享数据库。
