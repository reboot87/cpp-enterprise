# 并发与执行模型

## 1. 选型

| 模型 | 适用 | 代价 |
|---|---|---|
| request-per-thread | 中低并发、阻塞式调用 | 线程数受内存/栈限制 |
| event loop + 线程池 | 高并发、短任务 | 禁止在循环里阻塞 |
| actor / 消息传递 | 状态隔离、复杂共享 | 消息拷贝与调度开销 |
| 协程/结构化并发 | 大量并发 IO | 生命周期与取消语义要清晰 |

选型写进 ADR;不同模型不要在同一共享状态上混用且无隔离。

## 2. 线程与队列规模

- 线程数默认 ≤ 2×CPU 核数;IO 密集型按 `核数 × (1 + 等待/计算)` 估算并实测。
- 线程/任务必须有名字,便于采样与排查。
- 队列必须有界;容量按延迟目标与吞吐用利特尔法则推算,不拍脑袋。
- 溢出策略显式:拒绝、背压、丢最旧;三选一,并计数。
- 监控队列深度、等待时间、拒绝数;深度持续接近上限即告警。

## 3. 取消与超时

- 每个异步任务持有取消令牌/截止时间;超时向下传播。
- 阻塞调用必须可中断(条件变量、poll、可取消 IO),禁止无限等待。
- 结构化并发:父任务负责等待/取消所有子任务;禁止孤儿线程。
- 关闭时先取消、再等待、最后释放;有明确截止时间。
- 取消后释放资源,不留半完成状态。

## 4. 同步原语

- 优先 `mutex` + RAII(`lock_guard`/`scoped_lock`);锁粒度最小。
- 禁止持锁做 IO、分配、日志、回调、用户代码。
- 锁层级写进文档并固定顺序;需要时 `try_lock` + 超时。
- 条件变量用谓词循环,防虚假唤醒。
- 原子默认 `seq_cst`;其他内存序必须注释并给出论证。
- 无锁结构需正确性证明、压力测试和 TSan;否则不用。
- 引用计数线程安全不代表对象线程安全。

## 5. 共享数据

- 优先不可变共享、写时复制、线程局部、消息传递。
- 禁止 double-checked locking,除非用 C++11 的线程安全静态局部。
- 缓存/注册表等共享结构明确并发访问规则(读多写少用读写锁或快照)。
- 跨线程传递对象明确所有权转移(移动后原对象不再使用)。

## 6. 信号与进程

- 信号处理器里只调用 async-signal-safe 函数;用 self-pipe/signalfd 转到事件循环处理。
- 多线程进程避免 `fork`;必须时子进程只调用 async-signal-safe 函数后立即 `exec`。
- 子进程/线程会继承句柄,显式关闭不需要的。
- 超时与终止:先请求退出,再强制,避免无界等待。

## 7. 嵌入、FFI 与插件

- 跨语言边界:异常不穿越;错误码/返回状态显式翻译。
- 所有权明确:谁分配谁释放;跨 ABI 用纯 C 结构 + `static_assert` 校验布局。
- Python 嵌入:明确 GIL 获取/释放策略;回调里避免长时间持 GIL;重计算释放 GIL。
- 脚本/插件隔离:按风险选择进程隔离或沙箱(seccomp/AppContainer/Job Object)。
- 插件有资源上限(CPU/内存/时间/并发)与权限最小化;崩溃不拖垮宿主。
- 宿主与插件使用同一编译器/标准库/CRT,否则只走 C ABI。

## 8. 验证

- TSan 干净;多线程压力测试覆盖竞争路径。
- 超时、取消、关闭、重复调用各有测试。
- 并发输入配 fuzz(状态机/协议解析)。
- 长稳测试观察线程数、句柄数、队列深度是否单调增长。

## 9. 反模式

- 线程池无界,或每请求 `std::thread`。
- 析构函数里等待线程,导致退出挂死。
- 用 `volatile` 做线程同步。
- 持锁调用回调,回调里再拿锁。
- 取消只设标志,阻塞调用永不返回。
- 无锁队列没有 ABA/内存序论证。
- 插件崩溃后宿主随之退出,没有隔离。
