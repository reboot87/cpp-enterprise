# 鲁棒性

目标:在坏输入、依赖故障、资源耗尽、流量突增、进程被杀的情况下,行为可预测、可恢复、不丢数据。

## 1. 故障模型(先列出来再设计)

- 瞬时故障:超时、连接重置、短暂不可用。
- 永久故障:依赖下线、磁盘满、权限错误。
- 部分故障:多副本中一部分失败、半开连接、部分写入。
- 资源耗尽:fd、内存、线程、连接池、队列、磁盘。
- 坏输入:超长、畸形、越界、编码错误、恶意构造。
- 进程级:崩溃、被杀、重启、时钟跳变、机器重启。

## 2. 资源与边界(MUST)

- 线程、连接、队列、缓存、重试、并发请求数全部有上限。
- 队列满时必须有显式策略:拒绝(带状态码)、背压、丢最旧;并计数、可观测。
- 资源在入口处做准入控制,不要等到 OOM 才失败。
- 内存分配失败要有处理路径,不在关键路径上无界增长。
- 文件描述符、临时文件、锁等资源必须在异常路径也释放(RAII)。

## 3. 超时、重试、熔断

- 每个外部调用(网络、磁盘、锁、子进程)都有超时;默认禁止无限等待。
- 超时要能传播:上游截止时间向下传递,避免下游还在算、上游已放弃。
- 重试只用于幂等操作;有次数上限、指数退避 + 抖动、总预算;禁止重试风暴。
- 熔断器有明确的失败阈值、半开探测、恢复条件,并暴露状态指标。
- 降级路径必须预先定义:返回缓存、返回部分结果、只读模式、关闭非核心功能。

## 4. 隔离与背压

- 慢依赖不能拖垮整个进程:线程池/队列/连接池按依赖隔离(bulkhead)。
- 一个请求/租户/插件的资源占用有上限,避免互相影响。
- 过载时优先保护已有请求,拒绝新请求而不是排队到超时。
- 健康检查区分 liveness 与 readiness;未就绪不接流量。

## 5. 关闭与恢复

- 优雅关闭有截止时间:停止接收 → 排空在途 → 释放资源 → 退出。
- 强制终止后可恢复:启动时做状态对账,避免半写状态被当成完整数据。
- 关键写入用原子替换或 WAL/事务;明确 fsync 语义,不假设落盘。
- 幂等启动:重复启动、并发启动不会破坏数据。
- 时钟回拨、时区变化不影响超时与过期判断(用单调时钟)。

## 6. 输入与安全边界

- 所有外部输入在边界校验:长度、类型、范围、编码、数量。
- 鉴权失败一律拒绝(fail closed),不降级为放行。
- 解析器必须能处理截断、嵌套过深、超大字段;配 fuzz。
- 错误信息不回显内部路径、堆栈、密钥。

## 7. 可观测性

- 失败分类计数:超时、拒绝、熔断、降级、重试、丢弃。
- 每个失败日志带:操作、关键参数、错误码、重试次数、耗时。
- 暴露队列深度、在途数、熔断状态、资源使用,便于定位。
- 不吞异常;捕获后要么处理,要么带上上下文重抛。

## 8. 验证(MUST)

| 方法 | 要求 |
|---|---|
| 故障注入 | 依赖超时/断开/返回错误/慢响应,系统行为符合预期 |
| 资源耗尽 | fd、内存、队列打满,拒绝而非崩溃 |
| 长稳 | ≥24h 混合负载,无内存单调增长、无句柄泄漏 |
| fuzz | 解析器和协议入口,零 crash、零 UB |
| 杀进程 | kill -9 后重启,数据一致 |
| 过载 | 超过容量 2–5 倍,延迟可控、无雪崩 |

## 9. 反模式

- 只设连接超时不设读超时。
- 重试没有上限、没有退避、不区分幂等。
- 用 `catch (...)` 把故障变成静默。
- 无界队列"吸收"过载,最后一起超时。
- 关闭时直接 `exit()`,在途请求被截断。
- 依赖"下游永远可用"的设计。
- 只在开发机测过正常路径。
