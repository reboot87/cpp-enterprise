# 配置、数据与编码

## 1. 配置

- 配置有 schema,启动时校验;非法配置立即失败并给出字段路径。
- 优先级固定:命令行 > 环境变量 > 配置文件 > 默认值;文档写清楚。
- 配置在启动后不可变(或明确热更新范围与原子性)。
- 配置版本化;旧配置在新版本要么兼容,要么给出迁移工具。
- 配置里禁止放密钥;敏感值走 secret store/环境注入。
- 默认值必须安全(默认关闭调试端点、默认开启鉴权,除非明确说明)。

## 2. 密钥

- 只从 KMS/secret store/环境注入;不写仓库、镜像、日志、配置样例。
- 支持轮换;轮换不需要停机。
- 代码里只出现引用名,不出现值。

## 3. 序列化与协议

- 每个持久化/传输格式有显式版本字段。
- 只增不改:新增字段可选、有默认;删除先弃用。
- 未知字段保留并透传(中间层不得丢弃)。
- 禁止 `memcpy` 结构体做线格式;用显式字段编码,固定宽度整数 + 明确字节序。
- JSON:数字精度与整数范围明确;禁止依赖键顺序;限制深度与大小。
- 兼容测试:新读旧、旧读新、混合版本各一组。

## 4. 持久化与迁移

- schema 变更走迁移脚本,版本记录在库内。
- 迁移前向兼容:旧代码能在新 schema 上运行至少一个版本。
- 破坏性变更分两步(先双写/双读,再删旧)。
- 备份与恢复演练有记录;迁移失败可回滚。
- 事务边界清晰;禁止跨服务长事务。

## 5. 编码与本地化

- 全链路 UTF-8;文件、协议、日志、配置一致。
- 禁止依赖系统 locale 解析数字/日期;显式指定格式。
- 时间:内部存 UTC,展示按用户时区;用单调时钟做超时。
- 跨机时间用 NTP/PTP 同步;不假设机器间时钟一致,跨服务排序用逻辑时间或 trace。
- 金额用最小货币单位整数 + 币种;禁止 `float`/`double` 表示金额。
- 时长/大小带单位后缀(`timeout_ms`、`size_bytes`)。
- 路径与文件名处理见 `cross-platform.md`;Unicode 归一化(NFC/NFD)在比较与存储时明确策略。

## 6. 兼容性

- 明确支持矩阵:旧版本客户端/配置/schema 与当前版本的组合。
- 弃用项有警告期、文档、迁移脚本;到期才删除。

## 7. 备份与灾备

- 明确 RPO(可丢多少数据)与 RTO(多久恢复),写入 NFR 目标表。
- 备份加密,异地/不可变存储;备份账号与生产账号权限分离。
- 至少每季度做恢复演练并记录实际 RTO;没演练过的备份不算备份。
- 恢复流程有 runbook,包含依赖顺序与校验步骤。
- 多地域/多可用区说明故障切换条件与数据一致性。
- 日志、备份、审计数据有保留期与删除策略;到期自动清理并留记录。

## 8. 反模式

- 配置散落在代码常量里,部署时改代码。
- 用环境变量传长文本/结构化配置。
- 直接把结构体写到磁盘/网络。
- 依赖键顺序或浮点相等做协议判断。
- 用本地时区存时间。
- 迁移脚本只写"up",没有回滚或前滚说明。
